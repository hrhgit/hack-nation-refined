# 查询后的自动总结

选择地址或提交日期、房屋事实后，先显示完整法规结果，再自动生成总结。候选地址输入和页面筛选不调用模型。总结使用当前页面语言；每句引用跟在句子后，显示为小于正文的短标签，使用法规缩写、地区和条文编号区分，例如 `AB 12`、`CA §1950.5`、`LA §151.09`。同一法规的多个来源用小上标区分。完整引用名称保留在悬停提示和键盘阅读标签中。

点击引用先打开简短卡片，显示法规名称、当前适用状态、关键规定、地区、来源网站和官方/另行保存的来源标记；点击卡片里的“查看原文与完整判断”，再打开对应法规详情及原文前后文。卡片不调用模型，不影响法规列表位置；再次点击同一标签、点击外部、滚动页面或按 Escape 可关闭。适用、待确认、尚未生效/提案、已排除/被取代使用不同符号和颜色，另行保存的来源使用虚线边框。

总结区域预留高度，全部内容在区域内滚动阅读；逐段追加不推动法规列表或改变焦点。切换查询或语言会取消旧接收连接，返回浏览器保存的页面时重新获取结果。相同依据正在生成时共用一次调用；接收者全部离开后允许原调用完成并保存。

## 接口和保存

原有 `GET /api/lookup` 继续返回法规结果。新增接口：

```http
POST /api/summary
Content-Type: application/json

{"query":{"address_id":"A0001","as_of":"2026-10-01"},"language":"zh","fingerprint":"<SHA-256 of the displayed lookup evidence>"}
```

查询可含 `year_built`、`units`。浏览器和服务端共用 `web/static/summary-shared.js` 计算指纹：排除 `computed_ms`，其他查询依据按 JSON 的键排序后计算 SHA-256。服务器重新获取结果；指纹不符时返回 `409` / `stale_evidence`，页面先刷新法规结果再请求总结。

成功连接使用 `application/x-ndjson`，依次发送 `start`、若干 `paragraph`、`complete`。段落形状：

```json
{"type":"paragraph","paragraph":{"section":"overview","sentences":[{"text":"本句解释。","refs":[{"rule_id":"r-0001","source_index":0,"citation":"AB 12","doc_id":"D007","origin":"starter","url":"https://example.org/law","source_href":"/api/source?doc_id=D007&quote=...","result":"applies","conflict_flag":false}]}]}}
```

`section` 为 `overview`、`applicability`、`uncertainty`。模型只能引用服务端分配的来源编号及已有适用状态；服务端检查每句引用，补齐真实来源信息，再发给浏览器。有冲突的来源和未知、提案、未生效、被取代及排除项只能进入不确定事项。排除项的引用 `result` 为 `null`。正文、数值、条件、例外、日期、缺失事实和来源均保留；去掉重复的判断步骤和已在来源数组内的重复字段。

总结复用依据包含查询内容指纹、语言、模型和请求地址、总结指令、版本及模型生成设置。成功结果原子写入 `work/summary/cache/`，每次实际调用记录写入 `work/summary/runs/`，均由 Git 忽略。配置密钥不进入返回、缓存或记录。同一总结仅在服务进程内合并正在运行的调用；不同服务进程之间不合并，但可读取已完成缓存。

缺少密钥、连接中断、无效引用、状态不一致或未完整结束时，生成失败；已出现段落保留并标记未完成，失败结果不作为成功缓存。没有查询结果时直接返回空结果说明，不调用模型。资料未处理完时，页面单独显示已处理比例。保留法规列表和手动重试，不添加应用超时、输出长度限制、自动重试或自动切换模型。

## 模型和验证边界

总结默认复用 `.env` 中的 DeepSeek 模型，使用 `thinking.type=disabled` 直接整理已经计算好的判断。此设置只作用于总结。DeepSeek 默认先思考再输出正文，因此逐段接收本身不能消除这部分等待；相关参数见 [DeepSeek 官方说明](https://api-docs.deepseek.com/guides/thinking_mode/)。正文的引用和适用状态会经过程序检查，文字是否完全忠实仍需案例核对，不能宣称法律结论已核验。

自动化检查使用实际本地 HTTP 模拟服务，覆盖：网络分片和中文字符解析、正常结束及中途断开、错引用和错状态拒收、逐句引用对应、未完成不入缓存、手动重试、相同请求合并、无人接收时完成、重启复用、查询事实/法规/处理进度/语言/模型/指令版本变化失效，以及内容指纹不符时的刷新。执行 `npm run verify`；原始测试及模型输出只保留本地。
