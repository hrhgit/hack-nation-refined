# 第二版评测

保留第一版，补上条件、独立分组和 TypeScript 实际调用路径。所有分数都是本队自检，不是比赛评分。

## 输入与分组

- `cases.json` 是固定输入清单和评分端答案；`INPUTS.md` 展示实际新题原文、预期与真实材料清单。
- 112 个已在项目中出现过的包均为 `train`（开发检查），包括 65 个官方包、43 个研究补充包、4 个旧人工包。不能把研究补充原文当作比赛随包引用。
- 新增 16 个**虚构法规文本**：8 个验证包、8 个保留测试包；覆盖六类规则、正反例、户数矛盾、房东身份、日期边界、有效期、新楼利益、覆盖替代条件、提案、无相关规则和仅联邦法。
- 同一文件、完全重复文件和同一人工题型整组分配。真实材料全部视为已暴露，不伪造新的独立性。D046/D047 重复仍保留在开发组，审计列出，不重复声称独立样本。
- 新答案从写出的虚构条款构造，**尚未由另一人独立审阅**。真实条件答案沿用既有 28 条规则/75 个情境，来源文字、文件路径和原文哈希一起固定；没有宣称重新核验法律准确性。
- 新题是有限的边界练习，不是代表真实流量的随机样本。每个题型两份文本仍相关。模型最终测试默认不执行；不要用其失败来调整提示词后继续称为未见测试。

## 评分

不再把格式、引用和适用条件简单平均为一个能掩盖严重遗漏的高分。

- `rule_recall`：有人工答案的目标规则找到了多少；多数真实包仍没有完整答案，不能据此宣称全库无遗漏。
- `safe` / `exact`：没有不当隐藏规则 / 给出明确预期结论。沿用答案未能决定的情境不计入 exact。
- `missing_rules`、`wrong_exclusions`、`false_applies`、`unnecessary_unknown` 分别计数；漏整条规则也会增加应显示情境的错误排除数。
- `fields`：状态、日期、有效期、关系；虚构题还比较已明确给出的关键数字。
- `evidence`：原文片段可定位、条件/日期/数字没有被校验器报为无依据。**不是语义蕴含审查**：原文里有这句话，不自动证明它支持全部总结。关键词未命中之类的提示不冒充证据错误。
- `no_extra_rules` 只适用于有完整答案的虚构题；真实题答案不完整，不处罚未列出的合法规则。
- `all_required`：本题已定义的各项要求全部通过。虚构空答案题必须输出合法的零条回执；真正空响应不能冒充“没有规则”。该指标不是整份法律原文语义正确率。
- 每条结果带原始计数和分母，汇总区分完成率与已完成题得分，并报告重复运行不同的题目。不给小样本编造置信区间或显著性结论。

## 变更链题（覆盖第三阶段）

法规变动题（T1 到 T5）不是另一种提取：规则只提取一次，变动题是代码拿同一批规则做比较。所以要检查的是**提取的结果经过入库、地址查询、变更题之后，五道题是否还对**。`chain.py` 做这件事：

- 每个链题让模型提取一组文本包，再走正式的入库（含已审阅的 `work/overrides.json`）、查询引擎和变更追踪，只回答这一道变更题。入口是 `product.mjs` 的 `chain` 操作，用的仍是编译后的正式 TypeScript。
- **真实链** `CHAIN-T1` 到 `CHAIN-T5`：用比赛随包 `dev/change_tests.json` 的 `expected_behavior`，配合 500 个已解析地址，写成精确的地址集合（T1 全部加州地址先"尚未生效"后"适用"；T2 Hoboken 只出 HOB 规则、Jersey City 只出 JC 规则、Newark 都不出；T3 全部 NJ 地址、Hoboken 和 Jersey City 地址带冲突标记；T4 全部麻州地址为"提案"；T5 为空且公投记为已失败）。真实材料都已被看过，属于开发组。
- **构造链**：虚构文本，覆盖同样的情形，各两个变体：相对生效日期（"第 12 个月的第一天""批准后 90 天"）、州法禁止地方冲突条例、两个城市的边界、待决法案、被叫停的公投。关系、日期、状态、边界任何一步错了，变更题结果就会错。`chainrelative`、`chainpreempt`、`chainboundary` 在验证组，`chainpending`、`chainfailed` 在保留测试组（不要用来调提示词）。
- 分数单独记：`chain_checks`（通过的检查/全部检查）和 `all_required`（每个文本包格式干净、没有拒收记录、全部检查通过），不并进提取总分。
- 被多个链共用的文本包，每个重复只提取一次（T2 的四个包也用于 T3）。

运行：

```sh
python3 eval/v2/run.py --variant v4                       # 验证组，含构造链
python3 eval/v2/run.py --variant v4real --split train --cases CHAIN-T1,CHAIN-T2,CHAIN-T3,CHAIN-T4,CHAIN-T5
python3 -m unittest tests.test_eval_v2_chain              # 参考答案通过、故意写错会被发现，不调用模型
```

限制：真实链的期望来自随包说明和我们的地址解析，不是组织方评分；T1 的生效日期依赖我们手写并说明依据的 `ov-001`（原文未写日期）；构造链的答案尚无人独立审阅；Hoboken 和 Jersey City 条例原文的实际生效日期没有标准答案（原文没写，按"已在生效"处理）。

## 调用和隔离

`product.mjs` 仅导入编译后的正式 TypeScript 模块：与产品相同的 `converse`、校验器、卡片、自检工具、合并和 `LookupEngine`。`grading.py` 在调用结束后读答案，答案不传给模型。

模型 API 只能调用产品已有的 `read_card` / `check_record`；没有 shell、文件读取或答案查询工具。这是运行时隔离。当前编写者能查看全部文件，**不是分析员之间的访问隔离**。不要把 `cases.json`、`INPUTS.md` 或测试答案交给优化提示词的另一个智能体。

网页完整流程检查会启动真实 TypeScript HTTP 服务，在本地查询实际材料和引用来源；它不触发付费摘要或提交法规。合成流程另查：两份来源合并补足条件、州/城市规则优先关系、生效/到期切换后结果与解释一致。

## 重跑

在 `navigator/` 中执行：

```sh
npm run build
python3 eval/v2/audit.py
python3 -m unittest discover -s tests -p 'test_eval_v2*.py' -v
python3 eval/v2/run.py --variant v4 --dry-run
python3 eval/v2/run.py --variant v4
# 同一命令继续中断批次，只补尚未成功的 (case, rep)
python3 eval/v2/run.py --variant v4
# 明确选择最终检查时才执行；不要用于版本调整
python3 eval/v2/run.py --variant v5 --split test
# 历史回答复评分：单独目录，未知模型/用量不填零，不冒充新调用
python3 eval/v2/run.py --variant baseline --split train --replay eval/explore/conditions/agent4
```

本次真实基线保存在 `v3`（16/16）。随后仅修正运行记录对 Unicode 行分隔符的读取，提取/评分逻辑未改；旧轮仍按原快照保留。下一次运行使用 `v4`，之后相同参数续跑只补未成功位置。代码变化时改用新的版本名。

默认模型和认证仍使用现有 `.env` / 环境变量；默认两次重复。没有新增时长、输出长度、步骤上限或自动重试。`--cases` 可指定当前组内的包。

每轮 `run.json` 固定输入、来源、模型、提示词、正式代码、编译产物和评分代码的哈希；新轮次同时保存 `source_snapshot.json`（本次实际文件内容，已校验哈希，不含密钥），以便在有未提交改动的工作区复现；变更必须新建 variant，不能续写旧轮次。保存成功响应后才评分：即使评分中断也复用该次响应，不重新付费。错误单列 `errors.jsonl`，不占成功位置；运行中版本变化会停止。实际响应模型与请求不一致会报错，不猜测别名映射。提取轮次仅冻结实际依赖的模块，不把另一个任务的网页展示改动混入模型版本。

每个 API 调用保存实际模型、原始 usage、调用耗时及响应；缺失值为 null。费用目前为未知，未加入未经核实的价格。运行耗时另列，历史复评分不填模型延迟。

本地结果目录为 `runs/`，历史复评分为 `replay/`。两者被 Git 忽略；代码、输入、评分说明和 `BASELINE.md` 汇总可以提交。

HTML 中的均分必须结合 `summary.json` 完成率及本目录 `BASELINE.md` 阅读；不要将历史重评分和新调用相互比较成“模型提升”。
